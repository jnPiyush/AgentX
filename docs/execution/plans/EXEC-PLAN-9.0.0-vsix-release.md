## Surprises & Discoveries

- Observation: The source tree remains at `8.7.1`; the remembered `8.7.2`
  artifact is an immutable manual handoff, not the canonical source version.
  Evidence: `version.json`, `vscode-extension/package.json`, and repository
  release memory.
- Observation: `vscode-extension/package-lock.json` was CRLF, which violates the
  LF requirement the version stamper depends on. It was normalized to LF and the
  VSIX was repackaged from the corrected source.
  Evidence: byte-level line-ending check in `build/release-9.0.0-verify/`.
- Observation: Scrub reports pre-existing MEDIUM `duplicate-logic` findings in
  `install.ps1`, the Copilot CLI installers, and `.agentx/mcp-server/index.js`.
  None intersect this release diff, which changes version strings only.
  Evidence: `build/release-9.0.0-verify/iteration-3-gates-summary.txt`.

## Alternatives Considered

- Stamp only the VS Code extension manifest. Rejected because installers,
  packs, MCP metadata, documentation, and bundled assets would disagree.
- Replace every 8.x reference mechanically. Rejected because changelog and
  prior execution-plan references are historical evidence.
- Use the repository stamper, then audit active release surfaces and inspect
  one final VSIX. Chosen because it follows the existing release contract and
  minimizes manual edits.

## Decision Log

- Decision: Interpret the requested `9.0` release as SemVer `9.0.0`.
  Options Considered: `9.0`, `9.0.0`, `9.0.0-rc.1`.
  Chosen: `9.0.0`.
  Rationale: The repository stamper and VS Code extension manifest require
  `MAJOR.MINOR.PATCH`, and the user requested publishing preparation rather
  than a prerelease.
  Date/Author: 2026-08-25 / GitHub Copilot.
- Decision: Write the manual publish candidate to
  `build/manual-publish/agentx-9.0.0.vsix`.
  Options Considered: extension root, release-candidate folder, manual-publish
  folder.
  Chosen: manual-publish folder.
  Rationale: It matches the existing immutable manual-release handoff
  convention while keeping generated bytes outside tracked source.
  Date/Author: 2026-08-25 / GitHub Copilot.
- Decision: Advance the installer clean-install threshold from major 8 to major 9.
  Options Considered: leave at `-lt 8`; advance to `-lt 9`; document 9.0.0 as
  upgrade-compatible in place.
  Chosen: advance to `-lt 9`.
  Rationale: The constant was introduced at v8.0.0 so that crossing into a new
  major triggers the backup-and-clean-install path. Leaving it at 8 would let
  8.x users upgrade in place and retain orphaned assets. Independent review
  raised this as a MEDIUM finding.
  Date/Author: 2026-08-25 / GitHub Copilot.

## Follow-Up Debt

- `scripts/stamp-version.js` rewrites version literals but does not know about the
  installer major-version threshold, so the same constant can drift again at the
  next major release. Teaching the stamper (or a gate) about that constant was
  deliberately left out of this release to keep the diff surgical.
- `.gitattributes` does not pin LF for the manifests the stamper depends on, so a
  CRLF `package-lock.json` can recur on a fresh clone.
- `.agentx/install-manifest.json` still reports `8.4.45`; this is pre-existing
  drift unrelated to this release's change surface.

## Context and Orientation

updates extension and MCP package metadata, pack manifests and installers,
active documentation, and bundled VSIX assets. `CHANGELOG.md` and current
release summaries require editorial review because historical references must
not be rewritten.

## Idempotence and Recovery

The stamper accepts `--set 9.0.0` repeatedly and skips byte-identical writes.
If packaging fails, fix the reported prerequisite and rerun the same command.
Never overwrite an already published 9.0.0 artifact; use a new patch version.

## Rollback Plan

Before publication, remove the generated ignored VSIX and revert only the
9.0.0 release-preparation diff. After publication, preserve immutable 9.0.0
bytes and correct defects in a later patch release.
