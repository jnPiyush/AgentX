## Context and Orientation

AgentX has 365 tracked source files: 202 TypeScript, 86 PowerShell, 26 JavaScript/CommonJS,
22 Python, 18 shell, 10 TSX, and 2 PowerShell modules. The largest canonical
runtime files are `.agentx/agentx-cli.ps1`, `.agentx/agentic-runner.ps1`, and
several extension internals. Tests are split across PowerShell behavior suites,
1,015 VS Code extension tests, WhatsApp Node tests, and the MCP smoke test.

The canonical scrub implementation is `scripts/scrub.ps1`; the AgentX CLI
exposes it through `scrub`, `deslop`, and `antislop`. Bundled extension content is
generated by `vscode-extension/scripts/copy-assets.js` and must not be edited
independently.

## Plan of Work

First, make scrub output deterministic and reduce provable duplicate-detector
noise without weakening real duplicate detection. Second, re-run the canonical
audit and directly inspect the highest-confidence production findings. Third,
apply a small number of behavior-preserving optimizations with matching tests.
Finally, regenerate bundled assets if canonical runtime content changed, run all
affected gates, obtain independent review, and publish a findings/deferment report.

## Idempotence and Recovery

All scans are read-only and can be rerun. Each optimization is kept in a bounded
commit-ready diff. If a targeted or subsystem test fails, revert only that slice
and retain its audit finding as deferred work. Generated extension assets are
regenerated from canonical source rather than manually repaired.

## Rollback Plan

Before merge, revert individual optimization slices that fail verification. Do
not weaken tests or suppress findings to make a slice pass. If scanner precision
changes hide a known genuine fixture, restore the previous detector and redesign
the filter around explicit evidence.
